## 2. v40：修正调度顺序不一致

定位并修改了四处具体行为：

1. `V2CompoundPolicy.get_priority()` 在“没有模型动作，但仍有 deadline_deferred 链”的情况下，原先会采用 MLFQ 优先级；非边界 tick 清空 priorities 后又会落入 FCFS。修改后，可达标非锚链在这些路径中持续采用官方原生优先级。
2. `_schedule_process_list()` 原先反复用 `expected_first` 排序已执行的动作及后续续租。修改后，该顺序只用于首次执行见证，后续采用当前优先级。
3. `first_plan_for_action()` 原先先比较 MLFQ level，再比较达标可行性，与实际执行顺序不同。修改后，首步投影采用 forced、anchor、可达标原生顺序、不可达标原生顺序。
4. 非边界 `_schedule_running()` 原先按旧 running 队列顺序选择尾部换出对象。修改后，先应用当前 dispatch 顺序。

三项新增回归在 v39 上复现失败，在 v40 上通过。另加强了 controller：启动前校验当前 CPU 资格的版本和全部文件 SHA，并要求 GPU0 显存为 0 MiB。比较器改为读取当前冻结文件指定的验收收据，避免固定读取旧版本。

服务器验收：`CPU_QUALIFICATION_V42.json`，四项 gate PASS；5 项 dynamic batch、39 项 scheduler、27 项 rollout，以及新执行的真实 vLLM CPU runtime `V3_CPU_RUNTIME_46`。69 个冻结文件。

## 3. v41：让模型判定不可达标的链暂缓执行

仅靠优先级靠后，仍会让不可达标链在空余位置消耗计算。v41 增加 admission pause：存在模型判为可达标的 READY 链时，暂缓当前模型判为不可达标链的计算准入；它们的 compound KV 保持可整体回收。当没有可达标 READY 链时，恢复执行所有请求。

该规则依据当前 deadline、公开输入和同一预测器的风险工作量，未加入链 ID 特判，也未读入历史实际输出作为在线真值。已有未完成的有界 lease 得以执行完毕，保留同 ID 输出、compound 原子性和无重计算回退。

实际执行中观察到：主负载中段，链 0、4 只完成了阶段 0 的约 59、16 步；最新 batch 由链 1、2、3、5 组成。说明暂停真实生效。但它没有解决较晚截止、仍可达标的链与紧迫链之间的 KV 竞争。

服务器验收：`CPU_QUALIFICATION_V43.json`，四项 gate PASS；5 项 dynamic batch、42 项 scheduler、28 项 rollout，以及新执行的真实 vLLM CPU runtime `V3_CPU_RUNTIME_47`。69 个冻结文件。

## 5. v42：为紧迫链保留执行区间

v41 完整 trace 显示：链 3 约在 146 秒进入大 prefill、195 秒进入末段；链 5 约在 189 秒才进入末段，随后仍累计等待约 66 秒。仅暂停模型判为不可达标的链，仍不足以避免这些长上下文请求相互挤占 KV。

v42 在 v41 基础上增加较晚 deadline 链的暂缓条件：若其按同一风险预测计算的最迟开工时间，仍晚于当前最早可达标 READY 链的 deadline，并额外留出一帧及 KV 往返成本，才暂缓其计算。判断式为：

```text
D_later - risk_work_later >= min(D_attainable_READY)
                              + 50 * decode_seconds
                              + 2 * gpu_tokens_later * copy_seconds_per_token
```

`deadline_admission.py` 由 policy 与首步投影共同调用，避免两套口径。暂缓链的 compound KV 可以整体回收；当前有界 lease 先执行完毕，再允许在边界释放 incumbent。该准入规则补充了 v39 的持续续租行为。规则不包含链 ID 特判，也没有调整 deadline、资源或风险 q。

v42 的实际过程与假设一致：链 3 初期停留在阶段 0；链 1、2、5 分别约 163.2、185.0、214.5 秒完成并达标后，链 3 恢复执行，约 347.9 秒完成，仍在 480 秒时限内。链 0、4 随后完整结束。预测余量不是端到端数学保证，实际是否达标仍以客户端与比较器重算为准。

服务器 `CPU_QUALIFICATION_V44.json` 四项 gate PASS：70 个冻结文件；5 项 dynamic batch、44 项 scheduler、30 项 rollout，以及真实 CPU runtime `V3_CPU_RUNTIME_48`。runtime accepted/scheduled/executed=1/1/1，KV owner=0；受控 CPU selector 不作为自然性能证据。
