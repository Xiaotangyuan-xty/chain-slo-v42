# v44 完整 200 链实验：结果分析与独立核验

本轮已完成。在这一次有效的完整公开 trace 对照中，v44 C 按主指标战胜原生 JITServe A：官方缩放 SLO 达标链为 **45/200 对 7/200**，净增加 **38 条**，完成率由 **3.5% 提高至 22.5%（+19 个百分点）**。这是一组开发数据上的单次完整回放结果；稳定优势与泛化仍待验证。

兼容性验证、A、C 按顺序运行；A 使用物理 GPU0，C 使用物理 GPU1，两卡同型号 A40。C 控制器于北京时间 2026-11-01 10:35:45 完成清理，Mac 于 10:36:19 完成自动结果收集。独立核验再次查询到 GPU0/GPU1 均为 0 MiB、利用率 0%；最终审计记录两卡无计算进程，18080/65433 端口已释放。实验未使用 GPU2。

## 轨迹显示的收益与代价

本轮双方共同达标 4 条链（3、7、11、13）；C 新增 41 条，失去 A 的 3 条（1、9、10），净增 38 条。收益不是保住所有 A 的成功链，而是把有限时间分配给更多能够完成的链。

| 链类型 | 链总数 | A 达标 | C 达标 |
|---|---:|---:|---:|
| 四阶段 | 68 | 3 | **33** |
| 六阶段 | 132 | 4 | **12** |

收益主要集中在四阶段链。相对于主负载起点，前 200 秒 A/C 分别完成 5/19 条最终达标链，前 300 秒为 6/31 条；C 最后一条达标链在第 670.24 秒完成，此后继续排空所有剩余链。部分实例：

v44 使用整链完成收益相对剩余工作量排序、训练图提供的剩余工作估计、短期 KV 预留和运行保护。前 200 秒 C 的执行调用平均 batch 为 7.68，A 为 4.78；C 的预留快照平均空闲 GPU 块为 108.16/512，相比上一轮 v43 的约 247.62/512，早期空置现象有所改善。该值是快照均值，不是时间加权 GPU 利用率。全程平均实际 batch 仍很接近（A 3.576，C 3.588），整体执行器等待墙钟也接近；证据更支持“提前完成更多合适的链”，而非整体计算速度大幅提升。以上属于轨迹关联，尚无消融实验将收益归因到某一单独组件。

仍有明显不足：C 的 155 条链超时，80/120 秒两档预算的 50 条链均未达标；六阶段 360 秒预算组也是 0/32。平均 JCT 上升，说明更多链被推迟。C 的抢占次数略高于 A，尽管换入换出块量更低。

## 必须保留的两个边界

**原生 A 存在未解释的跨轮波动。** 上一轮有效 stage13 为 A=16、v43 C=3，本轮为 A=7、v44 C=45。跨轮检查确认 A 的资源、输入、生成参数、deadline、输出长度及停止字段一致，启动器逐字节一致；协议的 trace、阶段数、宽度、到达计划与生成配置也一致。然而 A 两次运行完整输出序列仅 383/1,204 相同，达标集合保留 5 条、失去 11 条、新增 2 条。例如链 179 的 JCT 从 237.82 秒变为 5,363.69 秒。现有证据没有定位这种调度/时序变化的具体原因，不能将其直接归因于某一种随机性。v44 的 45 也高于上一轮 A 的 16，但跨轮数字不能替代本轮配对比较，更不能作为稳定性结论。

**这是固定长度回放，尚未证明语义质量等价。** 本轮 A/C 完整输出 token 序列一致为 386/1,204 个请求，主负载为 380/1,197；输入、输出长度一致不意味着输出内容相同。没有记录 logits，也没有语义质量评估。本轮可以支撑该回放条件下的调度指标优势，不能据此声称真实 agent 任务质量保持不变。

完整公开 trace 包含此前已经检查过的开发前缀，且 A/C 在两张同型号卡上顺序运行；没有重复运行的方差估计、交换 GPU 的对照或独立 HOLDOUT 结果。下一步最有价值的是先保持 v44 不变，做配对重复和交换 GPU，再通过消融检查收益来源。本次状态查询没有启动新 GPU 实验，没有修改既有回执、v43 冻结版本或论文初稿。
