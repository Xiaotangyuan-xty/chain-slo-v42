# v47pro validation evidence

The scheduling origin is frozen v47, not the v50pro candidate scheduler. Parent
release snapshots remain unchanged. The new release uses shared comparison
infrastructure for prediction, ToT annotation, native credit and observation.

CPU history preserves ABI failures, the swap/recompute fixture correction and
all tested source snapshots. The published source must pass48 distinct CPU/native
tests. Separate tokenizer/stop/native-route/shared-cache qualifications bind each
GPU protocol. No CUDA context or model is constructed by those CPU tests.

The first normal-KV GPU prototype completed150 roots/230 calls and cleanup but
failed no_outside_candidate_selection. It is retained as FAILED_PRESERVED with
its original gate, receipts and compressed exact source packet. It is not a
valid performance result. Subsequent source corrects allowed masks/native-only
mode ownership before validation in fresh directories.

preparation_history includes an SSH connection timeout (no experiment launched),
a low-KV model-profile consistency assertion caught before any GPU launch, and
a superseded CPU-only prepared source. The latter directories are guarded from
launch; they are not additional GPU experiments or successful performance runs.

Release-source GPU development results and independent raw audits are listed in
GPU_VALIDATION.json. Each uses the same exact300s arrival prefix with full drain,
150 main roots and230 calls, not a complete one-hour replay. Warmup is excluded.
Each capacity has one run, not independent seeds or evidence of stability.
The primary future full-hour metric remains settled credit/3600. Development
windows explicitly use300 as denominator; full replay and drain are separate.
JCT is descriptive only; arrival error<=0.5s remains a technical gate.

The separate raw auditor does not import the runtime ledger calculator: it
retokenizes actual prompt/response text and reconstructs settlement events from
raw lifetime timestamps, then compares the exact ledger, window/full numerators
and the frozen native calculate_metrics oracle. It verifies all qualified source
hashes, identities/outputs, SLO, sampling, cleanup, mask/decision joins and KV.
Large raw traces stay in their immutable remote attempt directories; audits
record their SHA256 and byte size. No successful result substitutes a failed run.

A superseded source also passed its normal-KV GPU gate and separate raw audit,
but the trace exposed3003 replans, including2891 physical-state triggers. The
release refines those triggers to canonical residency/prefill state and capacity
release, excludes routine KV consumption/queue order, and uses repeated50-token
milestones. The valid earlier725.0633 credit/s in the300s window stays separate from release
source results; it is not removed or relabeled as a release-source measurement.
The newly added queue-order CPU fixture initially queried a private snapshot
before the normal next-tick lease registration; that failure and its original
source are retained. The corrected fixture runs four real steps and verifies
that both groups are resident before comparing reordered snapshots.
